Current Blocker — Step 3b Dynamic Routing

Error: CWWKX0229E: server responded with code 403 Forbidden on dynamicRouting setup CLI
Secondary error (plugin side): CWWKV0020E: Authentication to the Dynamic Routing REST service uses the admin role

What is confirmed working

  • Controller is running with dynamicRouting-1.0 + restConnector-2.0 loaded
  • plugin-cfg.xml is generated, plugin-key.kdb is created with correct certs (memberRoot, controllerRoot, default)
  • IHS starts and serves on port 8080
  • The /ibm/api/dynamicRouting endpoint exists (returns 500 only when called without Accept: application/json — the endpoint itself is healthy)

Root cause

restConnector-2.0 on Liberty 26 requires the calling user (admin) to be explicitly in the administrator-role. quickStartSecurity creates the user but does not automatically grant them the administrator-role for REST connector access. The <administrator-role><user>admin</user> dropin was added but the 403 persists — suggesting either a config merge issue or the dropin is not taking effect before the CLI runs.

What to diagnose in the next session

Run these on the VM and share output:

# 1. Confirm the dropin is present and correct
cat ~/Liberty-VM-Labs/installs/controller/wlp/usr/servers/controller/configDropins/overrides/dynamic-routing.xml

# 2. Check what security is actually loaded (may reveal conflicting config)
cat ~/Liberty-VM-Labs/installs/controller/wlp/usr/servers/controller/configDropins/overrides/collective-create.xml

# 3. Test if admin/admin can reach the REST JMX endpoint directly
curl -k -u admin:admin -w "\nHTTP %{http_code}\n" \
    https://localhost:9443/IBMJMXConnectorREST/mbeans 2>&1 | tail -5

# 4. Check controller log for security/role messages after last restart
grep -i "administrator\|CWWKS\|role\|security" \
    ~/Liberty-VM-Labs/installs/controller/wlp/usr/servers/controller/logs/messages.log | tail -20

Likely fix directions

  • If curl /IBMJMXConnectorREST/mbeans also returns 403: the administrator-role dropin is not merging correctly — try adding appSecurity-3.0 feature to the dropin
  • If curl returns 200: the timing fix isn't enough — the dynamicRouting setup command needs a longer wait or a retry loop
  • If collective-create.xml defines its own <administrator-role>: Liberty may not merge two — move everything into a single element
